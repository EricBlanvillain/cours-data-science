## Une requête se lit comme une phrase

<AnatomieRequete />

```python
sql("SELECT nom, vitesse FROM pokemon WHERE type1 = 'Fire' ORDER BY vitesse DESC LIMIT 3")
```

Les verbes de la séance 2 ont chacun leur traduction. Le tableau sert de fiche à retrouver ensuite.

| Le verbe | En SQL | En pandas | Exemple |
|---|---|---|---|
| Filtrer | `WHERE type1 = 'Fire'` | `df[df["type1"] == "Fire"]` | 52 Pokémon Feu |
| Trier | `ORDER BY vitesse DESC LIMIT 5` | `df.sort_values("vitesse", ascending=False).head(5)` | DeoxysSpeed Forme, 180 |
| Compter | `SELECT COUNT(*) … WHERE legendaire = 1` | `len(df[df["legendaire"] == 1])` | 65 légendaires |
| Regrouper | `SELECT type1, AVG(total) … GROUP BY type1` | `df.groupby("type1")["total"].mean()` | Dragon, 550,5 |
| Relier | `JOIN types AS t ON p.type1 = t.type` | `df.merge(types, left_on="type1", right_on="type")` | 466 lignes recollées |

## Relier deux tables

Une vraie base éparpille l'information : les Pokémon d'un côté, les forces et faiblesses de chaque type de l'autre.

<Jointure />

<details>
<summary>Les oubliés du JOIN</summary>

Huit types du dataset n'ont pas de ligne dans la table `types` : Bug, Dark, Dragon, Fairy, Ghost, Normal, Poison, Steel. Leurs 334 Pokémon disparaissent d'un `JOIN` simple, sans message d'erreur. C'est le piège classique : un résultat plus petit que prévu, et personne ne s'en aperçoit.

`LEFT JOIN` garde toutes les lignes de la table de gauche ; celles qui n'ont pas de correspondance ont des cases vides (`NULL`). Pour compter les oubliés : `WHERE t.type IS NULL`.

</details>
