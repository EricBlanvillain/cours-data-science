## Les vraies commandes

Le notebook crée un dossier d'entraînement et y tape les vraies commandes Git, une par cellule. Git répond en anglais : *untracked*, non suivi ; *modified*, modifié ; *deleted*, supprimé.

| La commande | Ce qu'elle fait | Quand |
|---|---|---|
| `git status` | dit où en est le dépôt | tout le temps |
| `git add notes.md` | choisit ce qui entre dans la sauvegarde | avant chaque commit |
| `git commit -m "…"` | crée le point de sauvegarde, avec un message | quand une étape est finie |
| `git log --oneline` | montre l'historique, le plus récent en haut | pour retrouver un commit |
| `git diff` | montre les lignes ajoutées et retirées | avant de sauvegarder |
| `git restore notes.md` | remet le fichier comme au dernier commit | après une erreur |

<details>
<summary>Ce qu'on ne sauvegarde jamais</summary>

Une clé d'API est un mot de passe pour un service. Publiée sur GitHub, elle est trouvée par des robots en quelques minutes. Le fichier `.gitignore` liste ce que Git doit faire semblant de ne pas voir : la clé, les gros fichiers de données. On l'écrit avant le premier `git add .`, et on le sauvegarde avec le reste.

</details>

## Envoyer et récupérer

Le notebook crée un deuxième dossier qui joue le rôle de GitHub, puis un « deuxième ordinateur ». `git push` envoie tes commits, `git clone` copie le dépôt ailleurs, `git pull` rapatrie ce qui a changé : le même historique sur les deux machines, sans compte ni réseau.

### À toi : tes notebooks en ligne
